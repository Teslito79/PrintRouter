## What it is

Windows desktop app, Python 3.14 + Tkinter, about 3,500 lines. Walk-in orders are priced, placed and printed from the Walk-in / Orders screens (2026-11-17); the app converts files to PDF, picks a Ricoh copier by rules (or by hand), sends with per-job driver settings through `driverprint.py` (PrintTicket to DEVMODE, pdfium drawing via ctypes, nothing saved to printer defaults) and prints a price receipt on the XP-80C thermal printer.

CorelDRAW templates (2026-11-06): `templates/<W>x<H>.cdr` per product size in mm; `printhub.choose_template` picks `<product id>.cdr`, then `cut_mm` WxH, then HxW, then `blank.cdr`, and Options.txt / the details show which. Size table: `PRINTHUB_SPEC.md` 3.4. Template choice, pieces per sheet, tray lines and the write-once copy live in `product_files.py` (2026-11-17), shared by PrintHub and walk-in orders. Layout done fills in pieces per sheet from `rules.json` `pieces_per_sheet` (size WxH/HxW, A4/A3; Tesla, 2026-11-12), never over a saved value; `Options.txt` names them.

Main menu (2026-11-15): ORCA opens on `mainmenu.py` (Walk-in and Orders = `walkin_screens.py`, PrintHub, Counter = `counter.py`, Prices = `costs.py`, Data = `toners.py`; `app.py` only starts it); one window at a time, Back on every screen, closing the menu quits. Counter adds up `print_log.csv` (columns since 2026-11-15: source, order, product, quantity, sheet size, color sides, bw sides, paper name; old lines still read). Prices holds the shop's costs (not `prices.json`) in `costs.json`, behind a password whose salted hash is in `prices_password.json` (delete it to reset); both local and gitignored. Costs show only in Counter and Prices, never in PrintHub or Walk-in. Counter's **Export PDF** (`counter_pdf.py`, pypdfium2 + embedded Arial, no new package) writes the period showing as a white A4 PDF, with Include costs / Include the list of jobs remembered in `counter_export.json` (local, gitignored).

Data (toners, 2026-11-16; called Toners until the rename the same day): fifth menu button, `toners.py` (module, class and local file names unchanged). Reads each copier's counters and toner levels over SNMP (own small v2c/v1 code, read-only, `public`) at start and every 10 min, one thread per copier, short timeouts; address from the queue's TCP/IP port or typed per copier. A level rising 30+ points = a toner change ("automatic" / "found at start"), or **Toner replaced** by hand; same toner within 24 h counts once. History: copies by the toner taken out (black: total counter; colours: colour counter, else total with a note) and averages. **Copier check** writes `copier_check.txt`. Local, gitignored: `toner_log.csv`, `toner_state.json`, `toner_settings.json`, `copier_check.txt`. Not yet tested on the real copiers. Spare toners per copier and colour ("Spare: 2", Stock… with − / + / typed count and minimum, red "Order more" / "None left", red dot on the menu's Data button); each recorded change takes one, removing it gives it back; `toner_stock.json` and `toner_stock_log.csv`, local and gitignored.

One ORCA only (2026-11-17_05): `app.py` first takes a named Windows mutex, `Local\ORCA-<hash of the ADMIN folder>` (`already_open.py`, ctypes), before any window or file. A second start brings the running ORCA's window to the front (restored if minimised; every window carries the property `ORCA.Instance`, set in `theme.dark_title_bar`) and exits touching nothing; if no window is found yet it says "ORCA is already open.". Windows frees the lock when the process ends (crash, Task Manager): no lock file. `ORCA.bat` runs `py -3.14 already_open.py` (exit 1 while ORCA is open) before its `git pull` and then skips the pull, so files never change under a running ORCA; that check sits on what was a comment line of the same byte length, so a copy of `ORCA.bat` running while `git pull` replaces it still reads on correctly. `PrintRouter.bat` (old shortcuts) still pulls before handing over (its first part must stay byte for byte), then ORCA.bat --no-update; the lock in `app.py` still stops a second ORCA.

Icon (2026-11-16): `icon.ico` on every window (`appicon.apply` on the root, `appicon.window` via `theme.dark_title_bar`), taskbar ID `ORCA.App`, `ORCA.lnk` icon fixed at start (`appicon.fix_shortcut`); never blocks the start. "Copydesk" was only a working name: don't rename the program.

### Decisions for stage 5 (2026-11-04)

- **Documents** (the website's document calculator) keep the existing `job.json` and print automatically after the staff press Start printing orders, as built in stage 3.
- **Products** (business cards, flyers, invitations, menus, ... 65 products on the website, A3 and smaller) are laid out **by the owner by hand in CorelDRAW**, using his own templates (e.g. 8 business cards per A4 with cut marks). The app does no imposition. Flow to build:
  - A product order arrives with the customer's file(s) and shows as **Waiting for layout**.
  - **Open file** button opens the customer file (default PDF program / CorelDRAW).
  - He exports the laid-out sheet as `print.pdf` into the same order (document) folder; the customer original stays untouched beside it.
  - The app detects `print.pdf` and moves the order to **Ready to print**; it prints `print.pdf` exactly as is (actual size, no n-up, no scaling).
  - Sheet count: typed by him, or worked out from cards per sheet (250 cards, 8 per sheet = 32 sheets).
- Quality: never rasterise a customer PDF on the way to the printer beyond what the existing driver path does; place and print it as is.
- Wrong-sized files (e.g. 95 x 60 mm for an 85 x 55 card) are fixed by him in CorelDRAW during layout; the website should also warn customers at upload (website's job).
- The website side still has to provide the paid orders: an authenticated way for this app to fetch them (e.g. an API route with a secret, returning paid orders and signed file links), download into a temp folder and rename into `orders/` with `order.json` written last (spec item 11). The product part of `job.json` is proposed in `PRINTHUB_SPEC.md` 3.4 and still has to be agreed with the Website chat; keep the formats in `PRINTHUB_SPEC.md` and the website's CLAUDE.md in step.
